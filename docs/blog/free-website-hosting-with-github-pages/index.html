Free Website Hosting with GitHub Pages

How to host a static website on GitHub Pages for free and map your own domain to it, with the GitHub and DNS steps and how to verify the setup.

15 June 2017·6 min read

Introduction

This article explains how to use GitHub Pages as a static web hosting server. Usually, if you want a website, you need to buy a domain and then buy storage space to keep the static files. There are many domain providers in the market. I did my domain registration through GoDaddy, but you can choose any domain provider you like.

Once you register a domain, you need a web server to serve your content. That content could be plain text, images, music, videos and so on. Like domain providers, there are many hosting providers. Most domain providers offer hosting as well, but you pay for it.

If you only need standard or static content for your website, and you don’t need any special server-side software (this is called static web hosting), there are providers that offer it at a lower price. For example, Amazon S3 static website hosting. With GitHub Pages, we don’t need to spend any money on this. We can host a website on GitHub without paying a single penny. This is useful for anyone who wants a site with static pages, such as a company profile, a business brochure, a blog or a personal profile.

Use the steps below to create a page on GitHub and map it to your domain.

Create a GitHub Pages site

The first step is creating a page. Follow the steps in the GitHub Pages documentation to create one. Don’t forget to name your repository with the .github.io suffix. For example, if your repository is called techsams, name it techsams.github.io. If you don’t use this suffix, the site still works, but the default page is rendered from the README.md file. With the suffix, GitHub picks index.html as the default page.

GitHub configuration

GitHub has good documentation on using a custom domain with GitHub Pages, but you have to follow several links to get the full picture. Use the steps below to add your domain to GitHub.

  1. Log in to GitHub. Select your Pages repository from Your repositories and click Settings.

  2. Scroll down until you see GitHub Pages. If you haven’t enabled Pages yet, select the branch that holds your web pages and click Save.

  3. Once Pages is enabled, enter your domain name and click Save. You will see a success message with your website address. As soon as you save the domain, GitHub adds a file called CNAME to your repository.

Once GitHub is configured, move on to the DNS configuration.

DNS configuration

To point your domain at GitHub, you need to know how to add DNS records with your DNS provider. If you don’t know how, contact your domain provider. Most providers have a web page for managing DNS records online. Here I use the GoDaddy DNS page for the examples.

There are two kinds of domains: subdomains and apex domains. A subdomain usually starts with www, for example www.techjira.com. An apex domain has no www, for example techjira.com. The DNS configuration is different for each.

  1. Log in to your DNS provider and open the DNS settings.

  2. Remove any existing entries. Make sure there are no conflicting A or CNAME records for the names you are configuring.

  3. If you use a subdomain (www), add a CNAME record with the value YOUR-GITHUB-USERNAME.github.io. For example, if your GitHub username is sivreddyp, the value is sivreddyp.github.io.

  4. If you use an apex domain, add A records pointing to GitHub’s Pages IP addresses: 185.199.108.153, 185.199.109.153, 185.199.110.153 and 185.199.111.153. Check GitHub’s custom domain documentation for the current list.

Custom error page

To serve your own page for HTTP 404 errors, create a 404.html file in the root folder of your Pages repository.

Key takeaway

GitHub Pages gives you free static hosting. Create a repository named <username>.github.io, enable Pages, map your domain with a CNAME or A record, and verify the DNS records. Once that’s done, your site is served from your own domain at no cost.
