React vs Angular: A Hands-On Comparison

Comparing React and Angular in practice: trends, learning curve, tooling, portability, architecture, templates, data binding, control statements and component communication, with side-by-side code.

16 August 2018·15 min read

Note on versions: This comparison was written against the React 16 and Angular 8 era. Some tooling mentioned below has since changed. create-react-app is deprecated, Protractor was removed in Angular 16, and Augury has been superseded by the official Angular DevTools. The concepts still hold, but check the current docs before starting a project.

Overview

There are many front-end frameworks and libraries, and the number grows every year. Among them, the most widely used are React and Angular. Both aim at the same goal, but they take different approaches. Choosing one is always a challenge, and many articles list the pros and cons of each. This article takes a different route: it compares them in practice. Before you choose, get hands-on with both and then decide which suits your needs.

Refer to npmtrends for binary download trends.

Learning curve

React

React is a JavaScript library developed and maintained by Facebook. It uses plain JavaScript, with HTML-like elements embedded in JavaScript through JSX. If you already know JavaScript and HTML, it is easy to pick up. Developers coming from .NET, Java or other backend technologies may find some concepts harder, and you need to understand state management properly.

React is a UI-only library. To build a full single-page application, you also need to choose other libraries:

  • Routing. Many routing libraries are available. See the React routing list.
  • State container. React has several ways to manage state. Redux is one of the best known.
  • AJAX library. You can choose any library for HTTP calls, such as the Fetch API, Rx.js, Axios, jQuery or others.

This freedom means that when you move to another project with a different combination of libraries, you have to learn that stack as well.

Angular

Angular is a framework developed and maintained by Google. It provides a standard stack that is shared across applications. Angular uses TypeScript, a statically typed language, along with a built-in routing API, and Rx.js for AJAX. Because of static typing, developers from backend technologies like .NET and Java find the code easy to follow.

Angular has a standard stack, so you learn it once and use the same stack in every project. This reduces the learning effort. Angular does not stop you from choosing other tools. For example, you can use the Fetch API instead of Rx.js, or even use React as the view inside Angular.

Tools

IDE

The IDEs and editors most often used for React and Angular are:

  1. WebStorm
  2. VS Code
  3. Sublime Text
  4. Atom

I prefer WebStorm, but it is paid. If you want a free option, VS Code is a good choice. Both editors support React and Angular well.

Testing

Use the default testing tools that come with each framework rather than experimenting with alternatives.

  • React: See the React testing guide for the tools and frameworks available.
  • Angular: Angular uses Jasmine for unit tests. It used Protractor for functional tests, but Protractor was deprecated in Angular 12 and removed in Angular 16. Check the Angular testing guide for current recommendations.

Debugging

Most browsers have built-in developer tools for debugging both React and Angular applications. Other tools help you understand the application flow and change data on the fly.

  • React: The React DevTools extension lets you inspect the component hierarchy, props and state. Other React debugging tools are also available.
  • Angular: Angular DevTools is the official browser extension for inspecting components and their state. The older Augury extension is no longer maintained. See the Angular resources page for more tools.

Portability

The main challenge with front-end components is portability. A component built with one stack can only be used in that stack. For example, if you build a button component in React, you can use it only in React applications. Components tied to a stack cannot be reused in other stacks.

Angular custom elements let you package Angular components as custom elements and use them in React or other stacks. Angular elements are Angular components packaged as custom elements, a web standard for defining new HTML elements in a framework-agnostic way.

Architecture

React is a library that fits the view layer of an MVC model. As described in the learning curve section, React does not impose an application architecture. You choose and design the architecture yourself. React does follow a component model, so you build UI components and combine them on a page. The sections below show how.

Angular is a framework that follows the MVC pattern for applications. In practice, most front-end frameworks follow MV* patterns, where the controller is not used as a separate concept. Google describes Angular as MVW (Model-View-Whatever). Refer to the Angular architecture guide for details. Angular uses decorators for dependency injection. It also follows a component model, where each component combines templates, directives, pipes and services. The diagram below shows how they fit together.

Components communicate in two ways: by passing input values down, and by returning values up. The demo has two components, Menu and Body. When the user clicks a menu item, Menu returns the page name. Body takes that value and shows the matching content. Body takes page as input and onMenuSelection as a callback for output.

React uses props for both. You pass a value as a prop for input, and a function as a prop for output. See the StackBlitz demo.

Angular uses the @Input() decorator for input values, and the @Output() decorator with an EventEmitter for output. See the StackBlitz demo.

Conclusion

React and Angular each have their advantages and disadvantages. The main points are:

React uses a dynamically typed programming model with a store-based state approach. Facebook created React with the virtual DOM to solve a specific problem that is common to many web apps: displaying large amounts of data that change dynamically. JSX changes a number of HTML elements and attributes to work with React. Each project chooses its own stack to build the framework of the application, which increases the learning curve.

Angular uses a statically typed programming model with TypeScript. This makes code easier to understand and maintain in large projects. The cost is boilerplate and configuration when you build components. The Angular CLI reduces much of the manual configuration. Angular elements can be used with other frameworks, which improves reuse. Angular uses standard HTML elements and attributes, with an extra set of elements that separate JavaScript from HTML. It provides a standard stack, which reduces the learning curve, and it is easy to pick up for developers with a .NET or Java background.

Key takeaway

Pick React if you want a lightweight view library and are happy to assemble your own stack. Pick Angular if you want a complete, opinionated framework with TypeScript and a standard set of tools, especially for large teams and projects.
